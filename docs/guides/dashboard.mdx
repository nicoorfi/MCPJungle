Mcpjungle let you manage your MCP servers and other entities through a Web UI.

Once your server is running, you can open this dashboard in your browser at [http://localhost:8080/](http://localhost:8080/) or whatever port the server process is listening on.

![MCPJungle dashboard UI](/images/dashboard-ui.png)

The Dashboard is currently only supported when running mcpjungle in [development mode](/core-concepts#development-mode-vs-enterprise-mode).

<Note>
  Dashboard is currently a Beta feature. The CLI remains the most complete management interface today, and the Dashboard UI is also available for local/dev visibility and common management tasks.
  Please report any issues or feedback you have.
</Note>

## Sign an upstream in again

Some upstream servers run their own OAuth sign-in and redirect the browser to `http://localhost:<port>` on the machine that runs mcpjungle. When their sign-in expires, their tools answer with a sign-in link instead of a result. mcpjungle notices the link, and the connection shows **Sign-in required** in the list and on its page.

When you open the dashboard from another machine, that redirect cannot reach the upstream. Sign in from the connection's page instead:

1. Click **Open sign-in page**. mcpjungle asks the upstream for a fresh link and opens it in a new tab.
2. Sign in. The tab ends on a "can't connect" page at `localhost`. That is expected.
3. Copy that page's address, paste it into the field, and click **Finish**.

mcpjungle delivers the address to the upstream on its own `127.0.0.1` and checks the result with one read-only tool call. It accepts only the address of a link the upstream handed out in the last 10 minutes, on the same port and path, and delivers each link once.
